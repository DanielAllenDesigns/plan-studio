# Chapter 1: Getting Started

This chapter takes you from a source checkout to a first drawn wall, and tours
the window: the menus, the three toolbars, the docks, the status bar, the
templates and the themes.

## 1.1 Installing from source

Plan Studio is built from source. Packages for macOS (arm64 and x86_64), Windows and Linux are produced by a
release workflow when a version tag such as `v0.1.0` is pushed (`.github/workflows/release.yml`), and attached to
the GitHub Release with the sample plans. They are plain archives, not installers: a zipped, ad-hoc-signed
`Plan Studio.app` on macOS, `plan-studio.exe` in a zip on Windows, and a tar.gz with the binary and a
`.desktop` file on Linux. Check the project's Releases page for whether a tag has been published; otherwise
build from source.

### Requirements

- A recent stable Rust toolchain. Install it with [rustup](https://rustup.rs).
  The workspace uses the 2021 edition and `eframe`/`egui` 0.31.
- A working OpenGL driver. The editor uses `eframe`'s `glow` backend, and the 3D
  view needs GLSL 1.40 (OpenGL 3.1) or ES 3.00. On Linux the build needs the GUI development
  packages that CI installs: `libgtk-3-dev libxkbcommon-dev libwayland-dev libxcb-render0-dev
  libxcb-shape0-dev libxcb-xfixes0-dev libgl1-mesa-dev`.
- macOS is the primary platform. Windows and Linux (X11 and Wayland) build, but
  several things are Mac-first: the hotkeys are Daniel's Mac bindings, and off
  macOS Chief's `Ctrl` is the Control key and the four-modifier chords become
  `Ctrl+Alt+...` chords (chapter 13).

### Build and run

From the repository root:

```bash
cargo run -p plan-app                 # debug build, opens the editor
cargo run --release -p plan-app       # optimized build (faster 3D and ray tracing)
cargo test -p plan-core               # unit tests for the model
cargo test --workspace                # every crate's tests (takes a while)
```

The binary is named `plan-studio`. The workspace profile sets `opt-level = 1`
for debug builds so the editor stays responsive; release builds use thin LTO.

### A macOS app bundle

After building, wrap the binary in a minimal `.app`:

```bash
cargo build --release -p plan-app
scripts/macos-bundle.sh release          # writes target/Plan Studio.app
```

The script takes the profile (`debug` or `release`) and an optional output
folder. The bundle is unsigned.

## 1.2 First launch

The program opens one untitled plan on the 1st Floor. The menu bar shows
`(unsaved)` at its right edge until you save. The canvas uses the Low Glare
theme (1.9) with a 12" reference grid and a 1" snap.

To draw a first room:

1. Press `Shift+Q` (or `2`) for Straight Exterior Wall.
2. Click four corners of a rectangle, then click the first corner again. The
   chain closes and ends. A room is detected inside and listed in the left
   Properties panel with its area.
3. Press `D, H` (or `3`) for Hinged Door and click a wall. A door is placed
   centered where you click.
4. Press `Shift+W` (or `4`) for Window and click another wall.
5. Press `Space` (or `1`) for Select Objects. Click a wall to see its handles
   and temporary dimensions. Double-click it to open the Wall Specification.
6. Press `Cmd+S` to save. Plan Studio asks for a `.psplan` file name.

`Cmd+Z` undoes each step by name ("Undo Move Wall"). `Esc` cancels the thing
you are doing, then returns to Select Objects.

### Sample plans

Three ready-made plans are in the `samples/` folder. Open one with File > Open Plan... (`Cmd+O`):

| File | What it is |
|---|---|
| `samples/ranch-3bed.psplan` | One-story 3 bedroom, 2 bath ranch with an attached 2-car garage (48' x 32' house, 22' x 22' garage), 11 rooms, 14 doors, 11 windows, 12 fixtures. |
| `samples/two-story-colonial.psplan` | Center-hall colonial, 40' x 32', with a foundation (48" stem wall), 1st Floor and 2nd Floor, four bedrooms up. |
| `samples/studio-adu.psplan` | A small studio accessory dwelling unit: 3 rooms, 349 sq ft. |

They start from Daniel's Chief X18 defaults. They are generated by `cargo run -p plan-core --example
make_samples`, so treat them as examples to open and take apart, not files to edit by hand. See
`samples/README.md`.

- **Menu bar** (top): File, Edit, Build, Terrain, Library, 3D, CAD, Tools, View,
  Window, Help, in Chief's order. Account is omitted (there is no licensing).
- **Toolbar row 1 and row 2**: the two horizontal bars. Each scrolls
  horizontally when the window is narrow.
- **View bar** (right edge): the vertical bar of browsers, zoom and display toggles.
- **Dock** (beside the view bar): opens when you click Library Browser,
  Project Browser or Active Layer Display Options. It is 3 panels, one at a time.
- **Properties panel** (left): a Plan Studio extra that Chief does not have.
  It holds the default exterior and interior wall type and height, grid and
  snap spacing, the canvas theme, the list of detected rooms with areas, and
  the selected wall's length, kind and thickness with an "Open Specification..."
  button. Its room areas are centerline areas; the room labels on the plan use
  interior areas (see chapter 4).
- **Status bar** (bottom): live cursor X and Y in feet-and-inches, a pending
  hotkey prefix (`D, ...`), the live readout while drawing, the name of the
  object snap in use, a one-line hint for the active tool, then the last
  message ("Not implemented yet", "Saved", an error).
- **Edit toolbar** (floating, bottom left of the canvas): appears when
  something is selected. Open Object, Delete Objects, Copy Selected Objects,
  Paste in Place, and Reverse Swing for doors. Fix Wall Connections is listed
  in the code but reports "not implemented yet" from this button.

## 1.4 The three toolbars

The bars are built to Chief's X18 Default Configuration (`docs/chief-x18-toolbars.md`):
dark gray `#3A3A3A`, 28 px buttons, flyout buttons with a small arrow.

- Click the icon half of a flyout button to activate the variant shown on its face.
- Click the arrow half to open the variant list. The variant you pick becomes the face.
- Hover any button for its name and hotkey.
- Dimmed buttons are not implemented yet (planned). Clicking one puts
  "Not implemented yet" in the status bar and changes nothing.
- Exactly one tool is active at a time. `Space` returns to Select Objects.

## 1.5 The docks

Click a view-bar toggle again to close its dock.

- **Active Layer Display Options**: a table of the plan's layers (Name, Used,
  Disp, Lock, Color) with a name filter and "Properties for Selected Layer".
  Turning off Disp hides a layer's objects at once. A **Layer Set** drop-down at the top switches the
  active layer set (a named table of per-layer display, lock, color and line weight overrides). Edits are
  undoable. Tools > Layer Settings > Display Options opens the same table as a window.
- **Project Browser**: Plan > Floors (click one to switch floors), **Cameras** (the plan's camera objects; click one to select it, switch to its floor and pan the plan to it; an unnamed camera shows as "Camera n"), **Saved Views** (the plan's saved plan views; click one to activate it, hover for its layer set and floor; the active view is highlighted) and **Layout** (the active layout's sheet size and scale, which View > Drawing Sheet and Print Preview draw, and Create Construction Set...). The layout sheet is kept for the session only; the plan file stores no layouts yet.
- **Library Browser**: a search field, a category tree and result rows with
  previews, plus the Chief Architect catalogs of your own Chief install (chapter 6).

## 1.6 The menus

The menu bar keeps Chief's titles and order: File, Edit, Build, Terrain, Library, 3D, CAD, Tools, View,
Window, Help. Build, Terrain and CAD are generated from the same flyout tables as the toolbars, so every
entry shows its icon, name and hotkey and unbuilt ones are dimmed. Working today:

- **File**: New Plan, Templates (Save Current Defaults as My Template..., Import Chief Template..., Reset to
  Chief X18 Template), Open Plan..., Save, Save As..., Export (DXF..., Elevation DXF..., Construction Set
  PDF..., glTF...), Import (Import Drawing (DXF)...), Quit (chapter 12).

  Framing, Delete Framing and the manual framing tools: chapter 11.11) and CAD > CAD to Walls... (12.4); **Terrain**: Create Terrain Perimeter, Terrain

## 1.7 Templates and Daniel's Chief defaults

Plan Studio starts the way Chief starts from a template plan. The defaults live
in `plan_core::PlanDefaults` (`crates/plan-core/src/defaults.rs`).
`PlanDefaults::chief_x18_daniel()` holds values captured from Daniel's Chief X18
template; the same values ship as
`crates/plan-app/assets/templates/chief-x18-daniel.json`, embedded in the
binary.

What the Chief X18 (Daniel) template sets:

| Group | Values |
|---|---|
| Exterior wall | Wall type `Stucco-6`, height 109 1/8" (9'-1 1/8"), roof Hip 8:12, overhang 16" |
| Interior wall | Wall type `Interior-4`, height 109 1/8" |
| Foundation wall | Wall type `Foundation-8`, height 48" |
| Wall types | `Stucco-6`, `Siding-6`, `Brick-6` and more, each a layer stack with one Main layer (for example Stucco 1 1/16", sheathing 9/16", Fir framing 5 1/2") |
| Interior door | 30" x 96", thickness 1 3/8", style Door P04, casing 3 1/2" x 3/4", swing 90 degrees |
| Exterior door | 36" x 96", thickness 1 3/4", casing 3 1/4" x 1" |
| Window | 32" x 72", sill 24", Single Casement, egress and tempered on |
| Base cabinet | 24" x 24" x 36", countertop 1 1/2", toe kick 4" x 3", Lincoln Door, knob |
| Wall cabinet | 24" x 12" x 30", bottom at 54" |
| Full height cabinet | 24" x 24" x 84" |
| Dimensions | "1/4" Scale Dimension Defaults": smallest fraction 1/8, unit indicators on, diagonal fractions at 60%, auto exterior offset 32" |
| Rooms | Ceiling 109 1/8", floor finish 3/4", ceiling finish 5/8", about 49 room types (Attic, Balcony, Bath ...) each with a Function and living-area flag |
| Layers | The 16-layer "Floor Plan" set (Walls, Normal; Walls, Invisible; Doors; Windows; Rooms; Room Labels; Dimensions, Manual; Dimensions, Automatic; Text; CAD, Default; Cabinets, Base; Cabinets, Wall; Electrical; Stairs; Roof Planes; Framing) |
| Text | Arial, 6" high in plan, 4.5" label style |
| Grid | 12" reference grid, 1" snap, 15 degree angle snap |

How defaults reach a plan:

- On startup the app loads `~/.plan-studio/defaults.json` if it exists, otherwise
  the embedded template. If the file cannot be read, the status bar says so and
  the template is used. Keys missing from the file fall back to the template.
- File > New Plan makes a project from the defaults' ceiling height and layer set.
- New walls take the exterior or interior wall type thickness and height. New
  doors take the interior door defaults, or the exterior door defaults on an
  exterior wall. New windows take the window defaults.
- File > Templates > Save Current Defaults as My Template... writes
  `~/.plan-studio/defaults.json`. Reset to Chief X18 Template restores the
  embedded values and deletes that file.
- File > Templates > **Import Chief Template...** picks a Chief `.plan`, `.tpl` or `.layout` file and seeds your
  defaults from what is stored in it: the names of wall types, layers and layer sets, text styles, dimension sets and
  saved plan views, the per-layer colors and line weights that could be decoded, and the decoded values (each wall type's real layer stack,
  the text styles' fonts and heights, the dimension sets' numbers; chapter 12.8). It then saves the result as your
  template. The file is read in place and never copied or changed. The status bar reports how many wall types
  and layers were added; the few wall types with no definition in the template have a thickness guessed from the name and are approximate.
- Edit > Default Settings... opens a searchable tree: Walls (Exterior, Interior,
  Foundation), Doors (Interior, Exterior), Windows, Dimension (Dimensions), Text
  (Text Styles), and Floors and Rooms (Room Types). Double-click a leaf (or press
  Edit) to open its dialog. The wall, door and window leaves edit the values new
  objects are placed from. **Dimensions** opens the Saved Dimension Defaults list
  (5.9), **Text Styles** the text style editor (5.9) and **Room Types** the room
  type list (4.10). The other Chief groups (Cabinets, Roofs, Stairs and so on) are
  not in the tree yet (planned).

Not stored in the defaults yet: muntin width, label options, the second casing
of a door.

Daniel's other Chief templates (26 `.plan` and `.layout` files in his Chief data folder) are read by the
`plan-chiefplan` crate and summarized in `docs/daniel-template-inventory.md`. Import Chief Template... is the way
to pull one into Plan Studio; automatic seeding on first launch and File > New Plan From Template... are (planned).

Daniel's Chief hotkeys are loaded at startup as well; see chapter 13.

## 1.9 Themes and UI brightness

The canvas has four themes, chosen in View > Canvas Theme or the Theme box in the
Properties panel:

| Theme | Use |
|---|---|
| Low Glare (default) | A warm mid-gray (about 196, 192, 184) with no pure whites. Made for people sensitive to light and brightness. |
| Paper | Off-white paper with a light grid, closest to a printed sheet. |
| Dark | A dark gray background with light linework. |
| High Contrast | White background and black linework. |

View > UI Brightness is a slider from 0.6 to 1.0. It dims the panels, text and
toolbar icons without touching the operating system's display brightness. Both
settings are saved to `~/.plan-studio/settings.json` and restored at launch.

The dialogs draw their previews like a drawing sheet (off-white), so they stay
readable at any brightness.

## 1.10 Files and settings

| What | Where |
|---|---|
| Your plans | Wherever you save them, as `.psplan` JSON (File > Save As...) |
| Theme and brightness, and the Chief catalog choice (`chief_catalogs`: on/off and an install-folder override) | `~/.plan-studio/settings.json` |
| Saved template defaults | `~/.plan-studio/defaults.json` |
| Hotkey edits | `~/.plan-studio/hotkeys.json` |
| Chief catalog index (file paths, sizes, modification times and catalog UUIDs the Library Browser's Chief nodes use to find your catalogs quickly) | `~/.plan-studio/chief-catalog-index.json` |

The settings folder is found from `HOME`, else `USERPROFILE`, else `HOMEDRIVE` plus
`HOMEPATH`, so it works on Windows as well. Undo keeps 100 steps.
Autosave and backups are planned.
